# PR 内容作成スキル

ブランチのコミット履歴と差分を分析し、`.github/PULL_REQUEST_TEMPLATE/default_pr.md` のテンプレートに沿った PR のタイトルと本文を作成する。**`gh pr create` は実行しない**。PRの作成自体はユーザー自身が行う。

## 手順

1. 以下を実行し、現在のブランチの情報を収集する:
   - `bash .claude/skills/create-pr/collect-branch-info.sh [base_branch]` でブランチ名・コミット一覧・変更概要・差分を一括取得（デフォルトのベースブランチは `develop`）
   - `.github/PULL_REQUEST_TEMPLATE/default_pr.md` を読んでテンプレートを確認（存在しない場合は下記の「テンプレート不在時」のデフォルト構成を使う）

   ベースブランチは基本的に `develop` とするが、`develop` が存在しない、または明らかに派生元と異なる場合はユーザーに確認する。

2. 収集した情報をもとに PR のタイトルと本文を作成する:
   - **タイトル**: コミットメッセージの内容を要約し、conventional commit 形式 (`feat:`, `fix:`, `refactor:`, `chore:`) で 70 文字以内にする
   - **本文**: テンプレートの各セクションを埋める
     - `# 概要`: PR 全体の目的を 1-2 文で説明
     - `## 実施した内容`: コミット単位で箇条書き。各コミットが何をしたか簡潔に記述
     - `## チェックリスト`: テンプレートのチェックリストに該当する高奥があればチェックをつける。(`- [ ]` を `- [x]` に変更)
     - `## 備考`: 特筆すべき設計判断やレビュー時の注意点があれば記載。なければ「なし」
     - `## 関連 Issue`: ブランチ名やコミットメッセージから明確に Issue 番号が読み取れる場合のみ記載。確信が持てない場合は空欄にし、推測の Issue 番号は記載しない

   ### テンプレート不在時

   テンプレートファイルが見つからない場合は、上記と同じセクション構成（概要・実施した内容・チェックリスト・備考・関連Issue）をデフォルトとして使い、その旨をユーザーに一言伝える。
