## Project Overview

Thor is an AI-driven full-stack monorepo that extracts step count data from Apple Healthcare XML exports to estimate and visualize sleep patterns, with LLM-generated feedback via Ollama.

## Architecture

### Monorepo Structure

```
Thor-Monorepo/
├── frontend/          # Vite + React Router v7 (SPA) + TypeScript + Tailwind CSS v4
├── backend/           # FastAPI (Python 3.12+)
├── ollama/            # Modelfiles + setup.sh (builds thor-* models on the host)
├── Taskfile.yml       # Task runner configuration
└── docker-compose.yml # Infrastructure configuration
```

### Backend Architecture

```
backend/
├── main.py            # FastAPI app: CORS + router registration
├── templates/         # Jinja2 email templates (email_ja.html / email_en.html / style.css)
├── datastore/
│   ├── prompts/       # LLM system prompts: prompt-{ja,en}.md, specialized-prompt-{ja,en}.md
│   ├── models/        # Pre-trained K-means models (model_1.pkl … model_14.pkl)
│   ├── statistical_data/ # correction_value.json (survey-based time corrections)
│   ├── sample_data/   # Sample XML exports and reference outputs
│   ├── vault/         # Per-request saved JSON (step data, estimates, clusters)
│   └── models.json    # LLM model list, generated by ollama/setup.sh
└── src/
    ├── core/          # Shared utilities (Envs class, constants)
    ├── routers/       # FastAPI endpoint definitions (thin layer only)
    ├── schemas/       # Pydantic request/response models + pandera DataFrame schemas
    └── usecases/      # All business logic
        ├── extract_steps/ # Apple XML parsing
        ├── estimate_sleep/# K-means clustering → feature extraction → late-night detection → sleep time estimation
        ├── llm_feedback/  # Ollama integration (via OpenAI-compatible SDK)
        └── via_email/     # SMTP email delivery with Jinja2 templates
```

**Design principles:**
- `routers/` must only contain endpoint definitions — business logic goes in `usecases/`
- `schemas/` holds all Pydantic models
- `core/` contains shared utilities: `load_env.py` (Envs class) and `constants.py`
- Debug output: when `IS_DEBUG=false`, `main.py` redirects `sys.stdout` to `/dev/null`, so `print()` is silenced outside debug mode
- CORS allows only `FRONTEND_ENDPOINT` and the `POST` method

### Backend API Endpoints (`/api/v1`)

1. **POST `/extract-steps`** — Parses Apple Healthcare XML, returns step data in 15-min intervals. Body is raw `text/xml`. Query params: `months_of_extract` (int) OR `start_date_of_extract`+`end_date_of_extract` (ISO 8601) — specifying both forms, or neither, is a 400; plus `include_recorded_sleep` (bool).
2. **POST `/estimate-sleep`** — Runs ML pipeline (K-means → feature extraction → late-night detection → bed/wake time estimation). Body: `id`, `step_data`, `answers`. Returns daily sleep estimates + available LLM models.
3. **POST `/feedback`** — Fetches LLM feedback from Ollama for a previously saved estimation (identified by `id`). Body: `id`, `llm` (model name), `lang` (`ja`/`en`), `is_specialized` (bool → selects the specialized prompt).
4. **POST `/via-email`** — One-shot workflow: extract → estimate → feedback → send email. Same query params as `/extract-steps`, plus FormData with `xml_file` (multipart) + `req` (JSON string of `answers`, `lang`, `is_specialized`, `email_to`).

**Data persistence pattern**: `extract-steps` generates a hash-based `id` and saves data as JSON to `VAULT_DIR`. Subsequent endpoints use this `id` to retrieve the saved data, enabling stateless requests. `/feedback` deliberately does not re-run estimation — it reads the saved estimate + cluster JSON so feedback can be regenerated repeatedly for the same estimation.

### Frontend Architecture

Vite SPA (React Router v7 in library mode; `app/main.tsx` → `app/root.tsx` → `app/routes/home.tsx`) with three UI states:
1. **Input** — Survey form (3 questions about phone habits + bedtime), XML file upload, optional email
2. **Loading** — Progress through extract → estimate → feedback stages
3. **Results** — Recharts timeline/bar charts for bed/wake times; LLM feedback rendered as Markdown via react-markdown

Key directories:
- `app/components/` — Feature components (survey-form, file-upload, result-view, ai-feedback, email-view, loading, header, locale-switcher)
- `app/components/ui/` — shadcn/ui primitives (button, card, chart, input, select, …). Add new ones with `task frontend -- pnpm dlx shadcn@latest add <component>`; do not hand-edit unless customizing.
- `app/utils/` — SWR mutation hooks (`use-extract-steps`, `use-estimate-sleep`, `use-ai-feedback`, `use-via-email`) + fetch wrappers in `api.ts`, shared types in `types.ts`
- `app/core/` — `constants.ts` (API endpoint, default extract query), `survey-schema.ts` (Zod validation)
- `app/lib/` — `utils.ts` (`cn` helper), `time-functions.ts` (chart time formatting)
- `app/locales/` — `translation-ja.json` and `translation-en.json` (i18next, configured in `app/i18n.ts`; fallback `ja`)

## Development Environment

### Container Services (docker-compose)

- `thor-workspace`: Dev Container (VSCode)
- `thor-backend`: FastAPI on port 8000
- `thor-frontend`: Vite dev server on port 5173
- `tunnel`: Cloudflare Tunnel (`cloudflared`) for external exposure

Ollama runs **on the host machine**, not in Compose — the backend reaches it via `host.docker.internal:11434`. Build the `thor-*` models with `./ollama/setup.sh`, which also regenerates `backend/datastore/models.json` (the model list returned by `/estimate-sleep`).

## Development Commands

This project uses Go-Task. View all commands with `task -l`.

### Servers

```bash
task backend:dev   # uvicorn with auto-reload on port 8000 (single worker)
task frontend:dev  # Vite HMR on port 5173
```

### Format, Lint & Type Check

```bash
task format           # Format backend (Ruff) + frontend (Prettier)
task lint             # Lint and auto-fix backend (Ruff) + frontend (ESLint)
task type-check       # TypeScript type check (frontend only; backend pyright is commented out)
task check            # CI-equivalent: format-check + lint-check + type-check (no auto-fix)
```

### Tests

```bash
task test             # Run all tests
task backend:test     # pytest -v
task frontend:test    # pnpm run test
```

**No test files exist yet** — pytest and Vitest are installed as dev dependencies, but `task test` currently has nothing to run, and it is intentionally excluded from `task check` / pre-push. `frontend:test` will also fail until a `test` script is added to `frontend/package.json`.

Run a single backend test file or function:
```bash
task backend -- uv run pytest path/to/test_file.py -v
task backend -- uv run pytest path/to/test_file.py::test_function_name -v
```

### Arbitrary Container Commands

```bash
task backend -- <command>   # Run in backend container (e.g., uv add <pkg>)
task frontend -- <command>  # Run in frontend container (e.g., pnpm add <pkg>)
```

## Commit Conventions

Git hooks via Lefthook:
- **pre-commit**: Auto-formats and lints changed files (glob-scoped, parallel)
- **commit-msg**: Rejects messages not starting with `feat|fix|refactor|chore: `
- **pre-push**: Runs `task pre-push` (format-check + lint-check + type-check, no auto-fix)

Commit message format: `<type>: <description>`

Allowed types: `feat`, `fix`, `refactor`, `chore`

## API Development Guide

### Receiving XML Files

For raw XML bodies (not JSON), use `Body()` directly — `BaseModel` schemas expect JSON and won't work:

```python
from fastapi import APIRouter, Body

@router.post("/extract-steps")
async def extract_steps(
    xml_data: str = Body(
        media_type="text/xml",
        description="XML file exported from Apple Healthcare",
        example="<?xml version=\"1.0\"?>..."
    )
):
    pass
```

```bash
curl -X POST -H 'Content-Type: text/xml' \
  --data-binary @export.xml \
  'http://localhost:8000/api/v1/extract-steps?months_of_extract=1'
```

### LLM Integration

The backend uses the OpenAI Python SDK pointed at the Ollama endpoint — not actual OpenAI. The `OLLAMA_ENDPOINT` env var configures this. Model names come from `backend/datastore/models.json`, generated by `ollama/setup.sh` from the host's `ollama list` (e.g., `thor-gemma3-27b:latest`).

System prompts live in `backend/datastore/prompts/` and are selected at request time by `lang` + `is_specialized`:
`{'specialized-' if is_specialized else ''}prompt-{lang}.md`. Browser flow uses the lightweight prompt/model (fast, chart-assisted); the email flow uses the specialized prompt (slower, comprehensive, text-only).
